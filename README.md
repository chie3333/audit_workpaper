# 감사조서 프로그램

> 실증절차 안내와 감사조서 작성을 연결하는 웹 도구 (1단계)

실증절차를 선택하면 단계별 안내를 보면서 실제 수행 내용을 입력하고, 저장한 기록으로 새 엑셀 조서를 만드는 로컬 웹 도구.
기획은 [docs/기획서.md](docs/기획서.md), 근거는 [docs/근거매핑_현금명세서대사.md](docs/근거매핑_현금명세서대사.md)를 따른다.
결정 이력은 [docs/결정기록.md](docs/결정기록.md), 작업 현황은 [docs/진행상황.md](docs/진행상황.md)에 있다.

**현재 상태: 1단계 v1 (단일 사용자, 로컬 실행)**
절차는 현금및현금성자산·장단기금융상품 계정의 두 가지다: *명세서 계산검증 및 보조부 대사*, *분류 검토(만기·사용제한)*. 분개장 업로드·계정 매핑(2단계)과 AI 매핑 보조(3단계)는 없다.
감사건마다 정산표·분개장을 두고 재무제표 → 정산표 → 계정원장 → 분개장으로 내려가며 볼 수 있다(지금은 가상 데이터만, 업로드 없음).
운영 중 AI를 호출하지 않는다.

## 실행

```bash
pip install -r requirements.txt
python scripts/seed_samples.py      # 가상 사례 넣기(대사 3종 + 분류 검토 1종, 가상 차이(주)에 정산표·분개장) — 선택
uvicorn app.main:app --reload       # http://localhost:8000
```

가상 사례가 근거 위치로 가리키는 회사 자료(명세서·보조원장·총계정원장·예금증서)는 `samples/sources/<사례>/`에 엑셀로 있다.
조서의 근거 위치(예: `명세_v1 명세!E4`)를 열면 같은 금액이 보인다. 다시 만들려면 `python scripts/make_sample_sources.py`.

테스트: `python -m pytest -q` (웹 계산과 엑셀 수식 결과를 대조하는 테스트는 LibreOffice가 있어야 실행된다)

## 동작하는 것

- 회사·보고기간별 조서 생성, 저장(리비전 누적), 다시 열어 수정, 이전 리비전 읽기 전용 보기
- 콘텐츠(절차 템플릿 + 계정 설정)를 읽어 단계별 안내와 입력란을 그림
  - 안내마다 내용 유형(원문 인용·근거 요약·보완 설명·가상 예시), 출처 위치, 미확인 표시, 검토 상태(기본 `AI 초안`)
  - 조서는 만들 때의 콘텐츠를 스냅샷으로 고정. 콘텐츠를 고치고 버전을 안 올리면 새 조서 생성이 막힘
- 계산: 행별 차이, 명세서 재계산 합계, 표시 합계 − 재계산 합계, 보조부 합계, 보조부 합계 − 총계정원장 잔액
  - 빈칸은 0으로 계산하지 않음. 빈칸이 있으면 합계·차이는 `미입력`
- 분기: 차이 → 발견 사항 기록 요구 / 자료 미입수 → 남은 작업 / 수정본 명세서 입수 → 이전 대사 보존 후 재대사 / 미해결 → 결론·엑셀에 표시
- 상태 3종 분리: 절차 수행(대체절차 수행 포함) · 발견 사항 처리 · 검토
- 자료 '등록'과 '증거 확인' 구분, 발견 사항의 '담당자 설명만'과 '자료로 재확인' 구분
- 분류 검토: 항목별 취득일·만기일·사용제한·회사 분류·감사인 판단 분류를 기록. 프로그램은 취득→만기, 대상일→만기 일수와
  분류별 합계(회사 vs 감사인 판단)만 계산하고 분류를 제안하지 않음. 분류가 다른 행은 재분류 금액으로 잡혀 발견 사항 기록을 요구
- 재무제표 → 정산표 → 계정원장 → 분개장 탐색 (홈의 감사건 옆 버튼)
  - 증감액(수정후 − 전기말)과 증감률(증감액 ÷ |전기말|)을 색으로 강조. 증가 ▲(붉은색), 감소 ▼(파란색), 전기 0원이면 '신규'
  - 재무제표: 표시 항목별 전기·당기·증감, 재무상태표 균형 점검, 당기순이익은 이익잉여금에 포함해 표시
  - 정산표: 계정별 전기말·수정전·수정분개·수정후·변동, 분개장에서 다시 쌓은 금액과의 대조, 차대 합계
  - 계정원장: 기초 잔액부터 분개를 쌓은 잔액, 원장 기말 − 정산표 수정후
  - 분개장: 전표별 라인과 차대 합계. 각 단계에서 그 계정과목을 참조하는 조서로 이동
- 조서의 '정산표 계정과목': 조서가 다루는 계정과목을 골라 전기말·수정후·변동을 참조로 표시. 조서 입력값은 바꾸지 않고,
  명세서 대사의 총계정원장 잔액 입력과 다르면 주의로 알림
- 재무제표 연결(감사기준서 330 문단 30)은 상태를 고르게 하고, 수행하지 않았으면 명시 문장을 만들지 않음
- 업무용 편집 잠금(잠긴 조서 수정 시 이유 기록). 최종 감사파일 취합·법정 보존 기능은 아님
- 엑셀: 한 조서 한 시트, 검토표 30행 초과 시 상세 시트. 차이·합계는 수식. 가상 데이터·미검토·미해결·원본/수정본 표시

## 동작하지 않는 것 (아직 없음)

- 증빙 파일 업로드·하이퍼링크·OCR (v1은 자료 식별정보와 위치만 기록)
- 로그인·다중 사용자·권한 (작성자 이름 칸은 있음)
- 정산표·분개장 업로드와 열 매핑, 공통 계정 매핑 (정산표·분개장은 가상 데이터만)
- 현금 외 다른 계정 콘텐츠
- 분류 검토의 서식 위치와 분류 기준(기업회계기준서) 문단 확인 — 안내는 '미확인'으로 표시됨
- 콘텐츠 편집 화면 (JSON 파일을 직접 고침)

## 구조

```
app/
  content.py   콘텐츠 로드·검증·결합 (근거매핑에 없는 문단 인용, 없는 계산·점검 규칙을 거부)
  engine.py    계산·표시 조건·남은 작업 점검 — 계산은 여기 한 곳에서만
  records.py   SQLite 저장 (회사 → 감사건 → 조서 → 리비전, 감사건별 정산표·분개장, 콘텐츠 스냅샷, 잠금 기록)
  export.py    엑셀 조서 생성
  samples.py   가상 사례 (대사 3종 + 분류 검토 1종)
  main.py      FastAPI
  static/      화면 (바닐라 JS)
content/
  sources.json                 출처 목록과 확인된 위치(근거매핑과 같아야 함)
  assertions.json              경영진 주장 (서식 A!A7:H10)
  templates/schedule_recon.json         공통 절차 템플릿: 명세서 대사
  templates/classification_review.json  공통 절차 템플릿: 분류 검토
  bindings/cash.schedule_recon.json         현금 계정 설정: 명세서 대사
  bindings/cash.classification_review.json  현금 계정 설정: 분류 검토
samples/sources/  가상 회사 자료 엑셀 (정상·차이·자료부족, scripts/make_sample_sources.py로 생성)
tests/        테스트 61개
```

### 다른 계정 추가

`content/bindings/`에 계정 설정 JSON을 하나 추가한다(자료명, 항목 열, 경영진 주장과 출처, 계정별 안내).
같은 템플릿으로 되면 코드 수정이 없다. 새 계산·점검이 필요하면 `engine.py`에 규칙을 추가하고 템플릿에서 이름으로 부른다.
콘텐츠 내용을 바꾸면 `version`을 올린다.

## 자료 사용

감사조서 서식과 회계감사기준 원문은 저장소에 넣지 않는다(한국공인회계사회 저작물). 콘텐츠에는 위치와 요약만 있다.
`data/`의 DB는 `.gitignore`로 제외한다. 실제 회사 자료를 넣었다면 공개 저장소에 올리지 않는다.
