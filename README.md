# Audit Workpaper

> 재무자료에서 감사조서까지, 실증절차의 수행 기록을 일관된 흐름으로 연결하는 로컬 웹 도구

`audit_workpaper`는 감사인이 절차 안내를 확인하면서 수행 내용과 발견 사항을 기록하고, 계산 결과와 검토 상태를 관리한 뒤 엑셀 조서로 내보낼 수 있도록 만든 프로토타입입니다.

현재는 **현금및현금성자산·장단기금융상품**을 대상으로 다음 두 절차를 지원합니다.

- 명세서 계산 검증 및 보조부·총계정원장 대사
- 만기·사용제한에 따른 분류 검토

운영 중 외부 AI API를 호출하지 않으며, 데이터와 조서 기록은 사용자의 로컬 SQLite 데이터베이스에 저장됩니다.

> [!IMPORTANT]
> 이 프로젝트는 단일 사용자용 로컬 프로토타입입니다. 감사인의 전문적 판단을 대신하지 않으며, 최종 감사파일 취합·법정 보존·권한 통제를 제공하는 감사문서 관리시스템이 아닙니다.

## 주요 기능

### 감사자료에서 조서까지

- 회사와 보고기간별 감사건 관리
- 재무제표·시산표 엑셀 양식 다운로드 및 업로드
- 시산표 계정과목과 재무제표 표시 항목 연결
- 감사인 수정분개 입력 및 정산표 계산
- 재무제표 → 정산표 → 계정원장 → 분개장 탐색
- 연결된 계정과목에서 해당 실증절차 조서 생성

### 절차 수행과 검토 기록

- 단계별 절차 안내, 입력란, 출처 위치 및 검토 상태 표시
- 명세서 재계산, 보조부·총계정원장 대사 및 차이 계산
- 자료 등록과 증거 확인을 별도 상태로 관리
- 차이, 자료 미입수, 수정본 입수 등 상황별 남은 작업 안내
- 수행 상태·발견 사항 처리 상태·검토 상태를 서로 독립적으로 관리
- 발견 사항, 후속 확인, 해결 근거 기록
- 조서 저장 시 새 리비전을 누적하고 과거 리비전은 읽기 전용으로 조회
- 편집 잠금 및 잠금 후 변경 사유 기록

### 검토와 산출물

- 보고기간별 조서·발견 사항 칸반 보드
- 미입력 항목, 미해결 차이, 상태 불일치 등 확인할 사항 표시
- 한 조서 단위의 엑셀 파일 생성
- 계산값은 화면과 엑셀에서 동일한 규칙을 사용
- 조서 생성 시점의 절차 콘텐츠를 스냅샷으로 보존

## 빠른 시작

### 요구 사항

- Python 3.10 이상
- 최신 웹 브라우저
- 선택 사항: LibreOffice — 엑셀 수식 결과까지 검증하는 일부 테스트에 필요

### 설치 및 실행

```bash
git clone https://github.com/chie3333/audit_workpaper.git
cd audit_workpaper

python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate

python -m pip install -r requirements.txt
python scripts/seed_samples.py   # 가상 사례 생성, 선택 사항
uvicorn app.main:app --reload
```

브라우저에서 [http://localhost:8000](http://localhost:8000)을 엽니다.

가상 사례를 넣으면 정상·차이·자료 부족 상황과 분류 검토 사례를 바로 확인할 수 있습니다. 이미 가상 사례가 있는 경우에는 중복 생성하지 않습니다.

## 기본 사용 흐름

```text
회사 생성
  → 보고기간 생성
  → 재무제표·시산표 업로드
  → 표시 항목 및 공통 계정 분류 확인
  → 감사인 수정분개 입력
  → 재무제표·정산표 증감 검토
  → 계정과목에서 절차 선택
  → 조서 작성·저장·검토
  → 엑셀 조서 다운로드
```

### 업로드 연습

가상 회사 자료와 업로드 연습용 파일은 `samples/sources/`에 있습니다.

- `정상/`: 명세서·보조원장·총계정원장이 일치하는 사례
- `차이/`: 명세서 차이, 수정분개, 분류 차이가 있는 사례
- `자료부족/`: 일부 감사자료가 입수되지 않은 사례

샘플 엑셀 파일을 다시 만들려면 다음 명령을 실행합니다.

```bash
python scripts/make_sample_sources.py
```

모든 샘플은 가상 데이터이며 실제 회사·금융기관·계좌·담당자와 관련이 없습니다.

## 현재 지원 범위

| 구분 | 지원 내용 |
|---|---|
| 실행 환경 | 단일 사용자, 로컬 실행 |
| 저장소 | SQLite (`data/audit.db`) |
| 대상 계정 | 현금및현금성자산·장단기금융상품 |
| 지원 절차 | 명세서 대사, 만기·사용제한 분류 검토 |
| 입력 자료 | 지정 양식의 재무제표·시산표, 앱에서 입력하는 수정분개 |
| 출력 | 조서별 `.xlsx` |
| 콘텐츠 관리 | JSON 기반 템플릿·계정 설정, 버전 및 스냅샷 관리 |
| AI 사용 | 운영 중 사용하지 않음 |

### 아직 지원하지 않는 기능

- 로그인, 다중 사용자 및 역할별 권한
- 증빙 파일 업로드, 하이퍼링크, OCR
- 더존·SAP 등 회계 프로그램의 원본 내보내기 양식 자동 인식
- 분개장 업로드와 원본 열 매핑
- 중요성 기준에 따른 증감 주의 표시
- 현금 외 계정에 대한 절차 콘텐츠
- 콘텐츠를 수정하는 관리자 화면
- 최종 감사파일 취합 및 법정 보존

자세한 작업 상태와 계획은 [진행상황](docs/진행상황.md)에서 확인할 수 있습니다.

## 설계 원칙

- **빈칸은 0이 아닙니다.** 필수 금액이 비어 있으면 관련 합계와 차이는 `미입력`으로 처리합니다.
- **프로그램이 판단을 확정하지 않습니다.** 분류와 감사 결론은 사용자가 판단하고 기록합니다.
- **상태를 임의로 연결하지 않습니다.** 절차 수행, 발견 사항 처리, 검토 상태는 각각 따로 관리합니다.
- **검증된 근거만 인용합니다.** 출처 매핑에 없는 기준서 문단은 생성하지 않고 `미확인`으로 남깁니다.
- **계산 규칙은 한곳에 둡니다.** 화면과 엑셀 출력이 `app/engine.py`의 동일한 계산 결과를 사용합니다.
- **과거 기록을 보존합니다.** 저장할 때마다 리비전을 추가하고, 조서는 생성 당시 콘텐츠 스냅샷을 유지합니다.
- **정산표는 참조자료입니다.** 정산표 금액으로 조서의 감사증거 입력값을 자동 대체하지 않습니다.

## 프로젝트 구조

```text
app/
├── main.py          FastAPI 서버와 API
├── engine.py        계산, 표시 조건, 남은 작업 점검
├── records.py       SQLite 저장, 리비전, 콘텐츠 스냅샷, 잠금
├── content.py       절차 콘텐츠 로드·검증·결합
├── imports.py       재무제표·시산표 엑셀 입출력
├── export.py        엑셀 조서 생성
├── samples.py       가상 감사 사례
└── static/          HTML, CSS, 바닐라 JavaScript 화면

content/
├── templates/       공통 절차 템플릿
├── bindings/        계정 분류와 절차 템플릿의 연결
├── account_groups.json
├── assertions.json
└── sources.json

docs/                기획서, 근거 매핑, 결정 기록, 진행 상황
samples/sources/     가상 회사 자료와 업로드 연습용 엑셀
scripts/             샘플 생성 및 엑셀 재계산 보조 스크립트
tests/               API, 계산, 분류, 장부, 엑셀 출력 테스트
```

## 다른 계정·절차 추가

기존 계산 규칙을 재사용할 수 있다면 코드를 수정하지 않고 콘텐츠를 추가할 수 있습니다.

1. `content/account_groups.json`에 필요한 공통 계정 분류를 추가합니다.
2. `content/bindings/`에 계정 설정 JSON을 추가합니다.
3. 기존 템플릿으로 표현할 수 없을 때만 `content/templates/`에 절차 템플릿을 추가합니다.
4. 새로운 계산이나 점검 규칙이 필요한 경우 `app/engine.py`에 구현합니다.
5. 콘텐츠 내용을 변경할 때는 반드시 `version`을 올립니다.
6. 테스트와 근거 매핑 문서를 함께 갱신합니다.

콘텐츠의 원문 인용·근거 요약은 `content/sources.json`의 확인된 위치와 일치해야 하며, 검증되지 않은 위치는 콘텐츠 검증 단계에서 거부됩니다.

## 테스트

```bash
python -m pytest -q
```

일부 테스트는 화면 계산과 생성된 엑셀 수식의 재계산 결과를 비교합니다. LibreOffice가 설치되어 있지 않으면 해당 테스트는 자동으로 건너뜁니다.

## 데이터와 보안

- 로컬 실행 데이터는 기본적으로 `data/audit.db`에 저장되며 Git에서 제외됩니다.
- 다른 DB 경로를 사용하려면 `AUDIT_WP_DB` 환경변수를 지정할 수 있습니다.
- 실제 회사 자료와 생성된 조서 파일은 공개 저장소에 커밋하지 마세요.
- 감사조서 서식 및 회계감사기준 원문은 저작권 문제로 저장소에 포함하지 않습니다. 콘텐츠에는 필요한 위치와 요약만 기록합니다.
